# 《交互式问答 Agent PRD（AI-native 简洁版）》

## 1. 产品定义

### 1.1 模块名称

交互式问答 Agent
Interactive Interview Agent

### 1.2 所属产品

Expert Brain Studio

### 1.3 一句话定义

**一个围绕专家知识榨取而设计的主动式 Agent，不是聊天机器人。**

### 1.4 核心目标

把行业专家脑中的 tacit knowledge，用最少交互成本，转成：

* 候选概念
* 候选规则
* 候选案例
* 候选边界 / 例外
* 待继续追问的问题

---

# 2. 设计原则

这版产品不走传统“复杂表单 + 多栏管理台”的思路，而走 **AI-native 单主线交互**。

## 原则 1：一个主任务流

用户进入后，不要面对复杂模块，只做一件事：

**围绕当前主题进行知识榨取。**

## 原则 2：AI 主动推进，不靠用户管理流程

不让专家自己想：

* 下一步该讲什么
* 应该怎么拆结构
* 哪些地方要补充

而是 Agent 主动做：

* 递进式追问
* 发现模糊点
* 发现边界缺口
* 总结当前理解

## 原则 3：实时“结构化理解”要可见

AI-native 不等于黑箱。
用户必须实时看到：

**系统已经理解了什么。**

## 原则 4：最少操作控件

整个界面只保留最必要动作：

* 回答
* 修正
* 跳过
* 结束
* 总结

## 原则 5：默认短回路，避免专家疲劳

每个回合都尽量小：

* 一次只问一个关键问题
* 一次只暴露最相关的候选知识
* 一次只要求最少修正

# 3. 用户与使用场景

## 3.1 主用户

### 行业专家

特征：

* 有经验，但不喜欢复杂系统
* 能通过说经验、举案例来表达
* 不愿意维护知识库
* 希望系统“懂行、懂上下文、少废话”

## 3.2 次用户

### 产品 / 知识工程 / 算法人员

他们主要消费这套系统产出的结构化资产，不是日常主操作者。

---

# 4. 产品目标

## 4.1 第一目标

**提高知识榨取深度**

不是简单问答，而是问出：

* 判断逻辑
* 决策变量
* 适用条件
* 反例
* 例外
* 证据依据

## 4.2 第二目标

**提高专家使用效率**

让专家觉得：

* 不费脑
* 不费操作
* 被理解
* 真有推进

## 4.3 第三目标

**提高结构化输出质量**

结果不是聊天记录，而是可进入后续链路的候选资产。

---

# 5. 非目标

本期不做：

* 不做多人协同
* 不做复杂图谱编辑
* 不做最终 wiki 共编
* 不做冲突裁决
* 不做 skill 编译
* 不做自动执行
* 不做复杂 BI 看板

本期只做：

**单专家、单主题、单 session 的高质量知识榨取。**

# 6. AI-native 产品形态

我建议这个模块用 **“单主屏 + 轻量结构抽屉”**，而不是传统三栏工作台。

---

## 6.1 总体页面形态

```text id="bjkjr9"
┌───────────────────────────────────────────────┐
│ 顶部：主题 + 当前阶段 + 结束 / 总结          │
├───────────────────────────────────────────────┤
│                                               │
│               主对话区                        │
│      系统提问 / 专家回答 / 阶段总结           │
│                                               │
│  [推荐追问方向 chips]                         │
│                                               │
│  输入框                                       │
│                                               │
├───────────────────────────────────────────────┤
│ 底部轻量结构条                                │

│ [展开查看]                                    │
└───────────────────────────────────────────────┘
```

### 核心思路

默认只让用户看到：

* 当前主题
* 当前问题
* 当前系统理解进度

只有在需要时，才展开“结构化细节”。

---

## 6.2 三层信息密度

### 第一层：默认层

用户默认只看到：

* 当前主题
* 当前问题
* 系统阶段性理解
* 底部已提取统计

这是最 AI-native 的使用层。

### 第二层：展开层

点击“展开查看”后，看到：

* 候选概念
* 候选规则
* 候选案例
* 候选边界

### 第三层：专家修正层

点击某项后才进入：

* 行内修正
* 标记待澄清
* 删除
* 合并

这能避免一开始把界面做得很重。

# 7. 核心交互流

## 7.1 用户进入

用户不是先填很多表单，而是进入一个极简启动页：

### 启动页字段

* 主题是什么？
* 你想让系统重点榨取什么？

例如：

* 主题：儿童学习桌垫主图背景选择
* 目标：沉淀判断背景选择的方法和例外情况

点击开始后进入主会话。

---

## 7.2 会话进行中

系统每轮做四件事：

1. 选一个高信息增益问题
2. 听专家回答
3. 实时抽取候选知识
4. 判断下一步问什么

---

## 7.3 阶段切换

系统不显式显示复杂流程图，而是以轻量状态提示告诉用户当前阶段：

* 正在澄清定义
* 正在抽取判断逻辑
* 正在补边界条件
* 正在追问反例
* 正在做阶段总结

---

## 7.4 会话收束

系统在合适时机主动提出：

* 我已经提取到几条规则
* 还有两个边界没补齐
* 现在结束，还是再补一个反例？

这个动作很 AI-native，因为系统在“主动管理访谈”。

# 8. 核心功能设计

---

## F1. 极简 Session 启动

### 目标

快速开始，不让用户卡在设置页面。

### 页面元素

* 输入主题
* 输入目标
* 可选：选择所属主干链路阶段

### 系统动作

* 生成初始 session context
* 生成首轮问题
* 推断可能相关的 stage / step

### 设计要求

* 不超过 3 个输入项
* 10 秒内可开始

---

## F2. 主动式提问引擎

### 目标

让 Agent 主动推进，而不是等用户驱动。

### 提问策略

系统每轮只问一个最重要的问题。

### 问题类型

按固定 taxonomy 生成：

* 定义类
* 判断类
* 条件类
* 反例类
* 例外类
* 证据类

### AI-native 要点

不要让用户选择问题类型。
系统根据当前缺口自动决定。

### 可视化方式

问题上方用很轻的标签显示：

* 当前在问：边界条件
* 当前在问：反例
* 当前在问：证据依据

---

## F3. 实时结构化理解

### 目标

让用户知道系统理解到了什么。

### 默认展示方式

底部条显示统计：

* 概念 3
* 规则 2
* 案例 1
* 边界 2

### 点击展开后显示

#### 候选概念

* 名称
* 一句话定义

#### 候选规则

* 规则陈述
* 适用条件（若已知）

#### 候选案例

* 一句话案例摘要

#### 候选边界

* 边界 / 例外陈述

### AI-native 要点

默认只显示“收敛后的理解”，不显示复杂 JSON、字段树。

---

## F4. 轻量修正机制

### 目标

用最少操作完成纠偏。

### 对每个候选项支持 4 个动作

* 确认
* 改一下
* 不对
* 以后再说

### 为什么这样设计

比传统：

* 编辑
* 删除
* 驳回
* 标记待澄清

更符合专家直觉。

### 系统内部映射

* 确认 → Confirmed
* 改一下 → Needs Clarification
* 不对 → Rejected
* 以后再说 → Deferred

---

## F5. 推荐追问 Chips

### 目标

给专家控制感，但不让他承担主流程设计。

### 展示形式

在输入框上方显示 2–4 个推荐追问方向：

* 追问反例
* 追问适用条件
* 追问失败案例
* 追问证据

### 作用

* 让用户能轻微 steer
* 让系统思路透明
* 避免完全黑箱

---

## F6. 阶段性总结卡

### 目标

避免长对话失控。

### 系统自动在以下情况触发

* 某类问题覆盖较充分
* 信息增益下降
* 专家表达较长
* 准备切阶段

### 总结卡内容

* 目前已提炼的关键规则
* 还缺什么
* 下一步建议问什么

### 用户操作

* 继续
* 换个方向
* 先结束

---

## F7. 会话收束与输出

### 目标

让 session 结束后得到结构化结果，而不是聊天记录。

### 输出对象

* Session Summary
* Candidate Concepts
* Candidate Heuristics
* Candidate Cases
* Candidate Boundaries
* Pending Questions

### UI 行为

结束时弹出总结页：

* 本次沉淀了什么
* 哪些内容已确认
* 哪些内容待后续补充

# 11. Agent 内部能力拆分

虽然前台看起来像一个 Agent，但内部建议拆 4 个逻辑子能力。

---

## A. Interview Planner

职责：

* 决定当前问哪类问题
* 决定是否切阶段
* 决定是否收束

---

## B. Question Generator

职责：

* 把问题类型转成自然、专业、不机械的问题文案

---

## C. Candidate Extractor

职责：

* 从专家回答中抽取：

  * candidate concepts
  * candidate heuristics
  * candidate cases
  * candidate boundaries
  * candidate signals

---

## D. Summarizer

职责：

* 生成阶段总结
* 生成会话总结
* 生成未解决问题列表

# 15. MVP 验收标准

---

## 产品侧

* 10 秒内可开始 session
* 能完成多轮访谈
* 能实时看到系统提炼结果
* 能轻量修正
* 能生成 summary

## 质量侧

单 session 平均至少产出：

* 候选概念 ≥ 3
* 候选规则 ≥ 2
* 候选案例 ≥ 1
* 候选边界 / 例外 ≥ 1

## 体验侧

* 专家能在 5 分钟内理解产品
* 专家觉得系统“少废话、真推进”
* 专家能感受到系统不是普通聊天机器人
