# 《Expert Brain Studio - 交互式问答台 PRD》

## 1. 文档信息

**模块名称**
交互式问答台 / Interactive Interview Console

**所属产品**
Expert Brain Studio

**版本**
PRD v1.0

**定位**
行业专家知识萃取前端的第一入口模块

**阶段目标**
优先实现 MVP 第一阶段，验证“专家知识是否能被高质量榨取出来”。

---

## 2. 背景与问题定义

### 2.1 背景

当前行业专家知识萃取常见方式包括：

* 人工访谈
* 问卷
* 会议纪要
* 零散文档整理
* 微信/飞书来回追问

这些方式存在几个核心问题：

1. **知识抽取浅**
   多数只能拿到表层经验，难以逼近专家真正的判断逻辑、边界条件和反例经验。

2. **结构化差**
   结果通常停留在纪要、录音、文档层面，难以进入后续本体化、标注、冲突治理和 skill 编译。

3. **追问不稳定**
   不同访谈人能力差异大，追问质量不稳定，容易遗漏关键变量、反例和例外条件。

4. **专家体验差**
   传统问卷太死板，访谈太费时间，专家容易疲劳，配合度低。

### 2.2 本模块要解决的问题

交互式问答台要解决的不是“做一个聊天框”，而是：

**通过递进式提问，把行业专家脑中的 tacit knowledge 高质量榨取出来，并沉淀成可进入后续知识生产链路的候选资产。**

---

## 3. 产品目标

## 3.1 核心目标

让系统能够围绕一个主题或对象，通过交互式问答完成以下四件事：

1. **抽出概念**
2. **抽出规则**
3. **抽出案例**
4. **抽出边界与反例**

## 3.2 产品目标拆解

### G1. 提升知识萃取深度

相比普通问答，系统能更有效追问：

* 为什么
* 何时成立
* 何时不成立
* 看什么信号
* 怎么取舍

### G2. 提升专家配合效率

让专家愿意持续使用，而不是只用一次。

### G3. 提升结构化程度

输出不是聊天记录，而是候选知识资产。

### G4. 为后续模块提供标准输入

输出可进入：

* 共编台
* 标注台
* 冲突裁决
* Skill Creator

---

## 4. 非目标

本期不做：

1. 不做最终 wiki 整理
2. 不做知识图谱可视化编辑
3. 不做冲突裁决
4. 不做多专家协同讨论
5. 不做 skill 编译
6. 不做自动业务执行
7. 不做复杂语音实时访谈

本期只做：

**单专家、单主题、单 session 的高质量知识榨取。**

## 5. 目标用户

## 5.1 主用户

### 行业专家

特征：

* 有大量经验，但表达方式偏口语或案例化
* 不愿意填复杂表格
* 愿意通过“对话 + 轻量修正”提供知识

需求：

* 表达轻松
* 不要被无意义问题打断
* 能看到系统是否真的理解自己
* 能及时修正系统理解偏差

## 5.2 次用户

### 产品经理 / 知识工程师

需求：

* 能看到 session 产出了什么
* 能知道哪些内容清晰，哪些内容未解决
* 能把输出接到后续共编和标注流程

### Agent 工程师

需求：

* 拿到结构化输出
* 拿到可复用的问题类型、session 状态和 candidate schema

### 用户故事 1

作为行业专家，我希望系统不是泛泛聊天，而是围绕一个主题持续追问，这样我能逐步把脑中的经验讲清楚。

### 用户故事 2

作为行业专家，我希望系统能追问反例、例外和边界，而不是只记录正向经验。

### 用户故事 3

作为行业专家，我希望系统能把我的表达实时整理成候选知识点，让我确认它有没有理解对。

### 用户故事 4

作为产品/知识工程师，我希望一个 session 结束后，不只是得到聊天记录，而是得到候选概念、规则、案例和未解决问题。

### 用户故事 5

作为后续模块的消费者，我希望交互式问答台输出标准化结构，便于进入共编、标注和 skill 化流程。

# 8. 功能详述

## F1. Session 创建

### 目标

建立一次知识萃取会话的上下文。

### 用户操作

专家进入问答台后，创建一个新的 Session。

### 必填字段

* Session 标题
* 主题类型
* 主题对象
* 目标说明

### 示例

* 标题：爆款主图策划经验萃取
* 主题类型：策略 / 视觉 / 内容
* 主题对象：小红书女装爆款主图
* 目标说明：沉淀“什么样的主图更容易出点击”的判断方法

### 系统行为

创建 session 后，系统生成：

* session_id
* 初始主题卡
* 初始问题计划
* 当前知识假设为空

### 输出

Session 元数据对象

---

## F2. 递进式问答引擎

### 目标

围绕当前主题动态生成高质量追问。

### 设计原则

提问不是随意的，而是围绕知识榨取目标编排。

### 问题类型框架

本期固定使用六类问题：

#### 1）定义类问题

目的：澄清概念和对象边界
示例：

* 你说的“高级感主图”具体指什么？
* 它和“干净感主图”有什么不同？

#### 2）判断类问题

目的：抽出规则与 heuristics
示例：

* 你判断一张图值不值得投的关键标准是什么？
* 你通常先看哪三个信号？

#### 3）条件类问题

目的：抽出适用范围
示例：

* 这种判断在什么情况下成立？
* 如果是新品期，是否还适用？

#### 4）反例类问题

目的：逼出失败经验和坑
示例：

* 有没有看起来符合，但最后效果不好的案例？
* 哪种图最容易误判？

#### 5）例外类问题

目的：识别边界外情况
示例：

* 有没有例外情况需要反过来做？
* 在哪些类目里这个经验会失效？

#### 6）证据类问题

目的：抽出数据/信号依据
示例：

* 你这样判断时会看哪些数据？
* 哪些现象会推翻你的判断？

### 问题生成逻辑

系统应结合以下内容生成下一问：

* 当前 session 目标
* 上一轮专家回答
* 当前已抽取的候选知识
* 当前缺失的关键槽位
* 问题多样性约束
* 避免重复约束

### 问题质量要求

每一问应满足：

* 与当前主题强相关
* 有明确抽取目标
* 避免空泛开放式废话
* 优先追问高信息增益点

### 本期限制

本期先不做复杂多轮规划器，只做：

* 模板驱动 + LLM 生成
* 基于缺失槽位的追问
* 基于矛盾/模糊点的追问

---

## F3. 候选知识实时抽取

### 目标

把专家回答实时抽取成候选资产，而不是只保存原始对话。

### 候选资产类型

本期支持 5 类：

1. Candidate Concept
2. Candidate Heuristic
3. Candidate Case
4. Candidate Signal
5. Candidate Boundary / Exception

### 抽取字段建议

#### Candidate Concept

* id
* label
* draft_definition
* aliases
* scope_hint
* source_turn_ids

#### Candidate Heuristic

* id
* statement
* rationale
* applicable_conditions
* non_applicable_conditions
* source_turn_ids

#### Candidate Case

* id
* title
* scenario
* action
* result
* lesson
* source_turn_ids

#### Candidate Signal

* id
* signal_name
* meaning
* positive_or_negative
* source_turn_ids

#### Candidate Boundary / Exception

* id
* boundary_statement
* trigger_condition
* effect
* source_turn_ids

### 展示方式

右侧实时展示“系统理解到的候选知识节点”。

每条候选知识支持：

* 确认
* 修改
* 删除
* 标记“待澄清”

---

## F4. 待追问问题池

### 目标

把“还没问清的问题”显式化，让 session 更像知识榨取而不是自由聊天。

### 问题池来源

系统从以下情况生成待追问问题：

* 定义不清
* 条件不全
* 没有反例
* 没有证据
* 有矛盾
* 出现模糊词
* 出现低置信候选资产

### 展示形态

页面右下角或下方显示“待追问问题池”。

每个问题项包含：

* 问题内容
* 问题类型
* 追问原因
* 优先级

### 操作

用户可：

* 点选立即追问
* 暂时跳过
* 标记不重要
* 改成手动问题

---

## F5. Session 收束与总结

### 目标

让一场访谈形成清晰结果，而不是无止境聊天。

### 结束条件

满足任一条件可触发收束：

* 达到目标问题覆盖阈值
* 专家主动结束
* 连续低信息增益
* 会话轮数达到上限

### 收束输出

系统自动生成本次 Session Summary：

#### 包含内容

* Session 主题总结
* 抽出的核心概念
* 抽出的核心规则
* 抽出的案例
* 抽出的边界/反例
* 未解决问题
* 推荐进入下一步的资产

### 输出去向

* 保存为 session summary
* 进入共编台待处理队列
* 进入标注台候选池

---

## F6. 专家修正与确认

### 目标

保证专家能及时纠偏，建立信任。

### 功能

专家在 session 过程中和结束后，都可以对系统抽取结果进行：

* 确认
* 改写
* 删除
* 合并
* 标注“说错了”
* 标注“后面再说”

### 本期重点

至少支持：

* 行内编辑
* 删除候选项
* 标记待澄清

---

# 10. 关键流程

## 流程 1：新建 Session

用户输入主题
→ 系统生成首轮问题
→ 进入问答

## 流程 2：进行中问答

专家回答
→ 系统实时抽取候选知识
→ 系统生成待追问问题
→ 系统选择下一问
→ 循环

## 流程 3：专家修正

专家看到右侧候选项
→ 修改 / 删除 / 确认
→ 系统更新当前知识状态

## 流程 4：收束总结

系统判断可以收束
→ 生成 summary
→ 专家确认
→ 输出到后续模块

# 12. Agent 逻辑设计

## 12.1 角色定义

本模块先只需要一个主 Agent，但内部可拆成 4 个逻辑子能力：

### A. Interview Planner

决定当前该问什么类型的问题

### B. Question Generator

生成具体问题文案

### C. Candidate Extractor

从专家回答中抽取候选资产

### D. Session Summarizer

在合适时机进行收束总结

---

## 12.2 最小策略

### 优先追问顺序建议

1. 定义是否清楚
2. 关键判断规则是否出现
3. 条件是否完整
4. 是否有反例
5. 是否有证据
6. 是否有例外

### 问题选择规则

* 优先追问高信息增益问题
* 避免连续问同类型问题
* 避免重复表达同一问题
* 当专家明显疲劳时优先收束

* 问题递进合理率

* 专家修改率
* 专家确认率

# 14. MVP 验收标准

满足以下条件可视为本模块 MVP 验收通过：

### 用户层

* 专家可在 5 分钟内理解如何使用
* 专家可独立完成一次 session
* 专家主观上觉得“系统真的在追问关键点”

### 产品层

* 能创建、进行、结束 session
* 能实时看到候选知识项
* 能看到待追问问题池
* 能生成 summary

### 质量层

* 单 session 平均至少产出：

  * 3 个候选概念
  * 2 个候选规则
  * 1 个候选案例
  * 1 个边界/反例
* 候选资产专家可接受率 ≥ 60%
* 无效追问率 ≤ 20%

### 工程层

* session 数据可回放
* 候选资产可追踪到来源 turn
* 输出格式可被后续模块 ingest

# 16. 风险与应对

## 风险 1：问题问得很机械

应对：

* 固定问题类型框架
* 允许手动切换追问方向
* 引入去重和多样性约束

## 风险 2：抽取结果不准，专家失去信任

应对：

* 实时展示候选资产
* 强化修正入口
* 所有候选项都可编辑/删除

## 风险 3：session 太长，专家疲劳

应对：

* 设计收束逻辑
* 控制连续追问密度
* 增加阶段性总结

## 风险 4：最后还是只有聊天记录

应对：

* 强制结构化 candidate schema
* 强制 summary 输出
* 强制 source turn 追踪

# 19. 一句话总结

**交互式问答台不是聊天模块，而是专家知识榨取引擎。它的核心不是“答得像人”，而是“问得够深、抽得够准、收得够结构化”。**
